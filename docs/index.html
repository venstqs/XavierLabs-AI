Abstract

XavierLabs is a command-line tool that carries a research question all the way to a written paper. It searches the literature, proposes a hypothesis that can be tested, and has it reviewed before any code exists. It then writes a Python experiment, runs it in a sandbox, and repairs it from the traceback when it crashes. Every number in the final paper comes from code that actually ran, and you can open, rerun and audit that code.

1Introduction

Computational research follows the same loop every time: read what is known, form a hypothesis, write a simulation, debug it, plot the results, and typeset the findings. Each step is slow, and the gap between a claim and the code behind it is where errors hide.

XavierLabs automates the loop and keeps that gap closed. You give it a question in plain language; it returns a folder containing the experiment, its recorded metrics, a figure, and the paper in PDF, HTML, LaTeX and Markdown.

2Method

Four agents work in sequence, as shown in Figure 1. The Ideator searches ArXiv and Semantic Scholar and drafts a hypothesis. The Reviewer scores it for novelty, rigor and feasibility, and sends weak ideas back for revision; if one is still rejected, the run stops before any code is written. The Coder writes a seeded, self-contained experiment, which runs in an offline Docker container or a restricted subprocess. A failed run returns its traceback to the Coder, which patches the script and tries again. The Synthesizer turns the recorded metrics into a figure and a paper.

3Example run

Figure 2 and Table 1 show what a run produces. The command below asked whether the Lion optimizer reaches a lower loss than AdamW on a non-convex surface. The first experiment crashed on a shape mismatch, the Coder fixed it, and the second run recorded the metrics plotted here.

4Usage

Run xavier with no arguments for an interactive console, or call a command directly (Table 2).

5Models

Any provider supported by LiteLLM works, including Groq, DeepSeek, OpenRouter, OpenAI, Anthropic and Gemini. To keep everything on your machine, point it at a local Ollama model; no API key is needed.
